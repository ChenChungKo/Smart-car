# 感知與定位架構（草案，尚未實作）

只用相機（前、後 CSI；雲台、左、右 USB）＋超音波＋紅外線。沒有 IMU、沒有光達。
目標：一條通用的資料流，取代目前「一個失敗補一條規則」的程式；日後加感測器只是多一種輸入。

## 一、分層與資料流

```
L1 感測器節點     CameraHub(5 支)   SonarNode(角度+讀數)   IRNode(6 顆)   CmdLog(指令速度)
                      │ 影像+時間戳        │ 射線+時間戳          │ 有/無+時間戳    │ vx,vy,wz+時間戳
L2 量測轉換       TagMeasurer         FootMeasurer          RangeMeasurer   ContactMeasurer
                  (影像→標籤位姿+Σ)   (影像→地面點+Σ)       (讀數→射線+錐角) (IR→弱接觸)
                      └────────────┬───────────┴───────────────┬───────────┘
L3 狀態                          Estimator(位姿+Σ)         WorldMap(佔用格)
L4 查詢                       pose(t), Σ(t)            clearance(車身範圍, 路徑)
L5 使用者                  現有停走式 route_follow（本里程碑）／連續控制器（下個里程碑）
```
每一層只依賴下一層的**資料型別**，不呼叫別層的內部函式。

## 二、量測資料型別（全部帶時間戳 t，單調時鐘）
- `TagObs(t, camera, tag_id, T_cam_tag, Σ)`：標籤位姿與共變異數（距離、入射角決定 Σ）。
- `GroundPts(t, camera, pts_car, Σ_pt, kind)`：kind = `hit`（腳線點，這裡有障礙）或 `bound`（相機底部看不到腳：「至少這麼近」）。
- `RangeObs(t, origin, direction, range, cone)`：超音波；射線上 range 之前是空的，終點是障礙（或牆）。
- `ContactObs(t, sensor, lit)`：紅外線；只當車身旁 ≤20 cm 有東西的弱證據。
- `Cmd(t, vx, vy, wz)`：指令速度；估計器的運動模型輸入。

## 三、估計器（位置）
- 狀態 [x, y, yaw] 與 Σ；另有慢變參數：轉彎比例、側移比例（取代現在的 learn_* 補丁）。
- 預測：指令速度積分；Σ 隨移動量增加，並做 P ← F P Fᵀ + Q（車頭不確定會傳到位置）。
- 更新：TagObs（所有相機）、RangeObs 對牆（垂直打牆時直接約束 x 或 y）、ContactObs（弱）。
- 異常量測：馬氏距離＋穩健損失降權，不是丟掉，也沒有「只取方向」這類特例。
- 晚到的量測：保留約 2 秒的狀態歷史，回到量測時間更新，再重做之後的預測。

## 四、地圖（障礙物）
- 世界座標佔用格，1～2 cm；log-odds；每個量測有逆感測器模型：
  - `hit`：該格加分，點與車之間的射線減分。
  - `bound`：只對射線上較近處減分（那裡是空的），不對遠處下結論。
  - 超音波：射線減分、終點加分，錐角內機率遞減。
  - IR：車身旁格子加一點分。
- 點的世界座標來自「量測 ⊕ 估計器位姿 ⊕ 位姿不確定性」，所以位置不準時，地圖的不確定性跟著變大。
- 方塊輪廓：連通區域＋已知尺寸擬合（沿用 obstacle_map.py）。
- 規劃唯一的問題：`clearance(車身範圍＋餘裕, 路徑)` 是否 > 0。

## 五、相機排程
- 每支相機有「角色」與頻率上限；CPU 超過預算就整體降頻（實測：5 支、每支 10 Hz、640×480 約 26% CPU；每張都偵測約 72%）。
- 前、後：沿車道標籤；右：離牆近的標籤與方塊側面；左：場地內部的標籤；雲台：腳線（靠近方塊時升頻）。
- 轉彎或速度過快（動態模糊）時降低標籤權重，不是關掉。

## 六、這個架構如何對應我們遇過的失敗（不再各補一條規則）
| 過去的補丁 | 在新架構裡 |
|---|---|
| 遠標籤只取車頭方向 | TagObs 的 Σ 隨距離變大，濾波器自己給小權重 |
| 位置被遠標籤取代 | 沒有任何路徑取代狀態，只有更新 |
| 死角三條規則 | `bound` 型量測 |
| 相機漏看就換超音波 | 兩者都寫進同一張地圖，衝突由 log-odds 解決 |
| 牆邊 IR 誤判 | IR 是弱證據，超音波與地圖共同決定 |
| 停車前掃描、靠牆停車 | 超音波垂直打牆就是一筆位置量測 |
| 通過時往外推、PASS_MARGIN | clearance 查詢，只剩一個安全餘裕 |

## 七、設定檔
- `vehicle`：車身尺寸、感測器安裝位置與內參檔、標籤地圖、場地尺寸（全是物理量或量測值）。
- `noise`：每種量測的雜訊模型（像素 σ、距離比例、超音波 σ…），每一項有單位與來源。
- 沒有「某情況用的門檻」。

## 八、沒有車子時可以先做的
1. 設計資料型別與介面（本檔）；為每種量測寫雜訊模型的推導。
2. 在模擬器產生同樣的量測型別，估計器與地圖在模擬器上單元測試。
3. 用已存的 669 張雲台畫面離線重播地圖。
4. 設計錄製格式（量測層，不是影像層，可重播）。

## 九、一定要在車子上做的
1. 左、右相機的外參與內參檢查（USB 相機 fx≠fy，要確認原因）。
2. 5 支相機＋偵測的 CPU 與 640×480／1280×960 的標籤精度比較。
3. 雜訊模型的實際數值（標籤 σ、超音波 σ、逆感測器模型的加分量）。
4. 多圈實車指標與基準比較。
